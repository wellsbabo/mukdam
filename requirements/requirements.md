## 1. 프로젝트 개요

### 1.1 서비스 한 줄 설명

소모임에서 기도제목과 묵상을 나누는 크리스천이, 자신의 기도제목과 묵상을
날짜별로 기록하고 다시 찾아볼 수 있는 개인용 iOS 앱.

### 1.2 해결하려는 문제

- 현재 사용자가 겪는 문제: 기도제목과 묵상 나눔 내용을 카카오톡 대화창이나
  메모장에 그때그때 적어두기 때문에 한곳에 모여 있지 않다.
- 기존 방식의 불편함:
  - 어느 날짜의 기도제목이었는지, 어느 날짜의 묵상이었는지 확인이 어렵다.
  - 카카오톡 대화 내용은 다른 대화에 섞여 밀려나고, 나중에 되짚어 보기 어렵다.
  - 묵상이 어느 성경 본문에 대한 것이었는지 함께 남기지 않아 기록의 맥락이
    사라진다.
- 이 프로젝트가 필요한 이유: 흩어진 기록을 한 앱에 모아 날짜와 성경 본문
  기준으로 축적하고, 소모임에서 나눌 때 바로 꺼내 쓸 수 있게 한다.

### 1.3 서비스 비전

기도제목과 묵상을 적는 일이 앱을 여는 순간 바로 시작될 만큼 가벼워지고, 시간이
지나면 그 기록이 자신의 신앙 여정을 되짚어 볼 수 있는 개인 기록장이 된다.
소모임에서 나눌 차례가 되면 그날의 기록을 그대로 꺼내어 읽거나 공유할 수 있다.

### 1.4 핵심 사용자

사용자 유형은 한 종류다. 관리자 역할은 없다.

| 사용자 | 원하는 것 | 현재 불편한 점 |
|---|---|---|
| 소모임 참여 크리스천 | 기도제목과 묵상을 날짜별로 빠르게 기록하고 다시 찾아보기 | 카카오톡·메모장에 흩어져 있어 날짜별 확인과 누적 관리가 안 됨 |

### 1.5 핵심 가치

- 사용자 관점: 날짜와 성경 본문이 함께 남는 개인 기록장. 몇 번의 조작으로 기록이
  끝난다.
- 운영자/관리자 관점: 관리자 역할이 없다. 서버와 계정을 두지 않아 운영 부담과
  운영비가 발생하지 않는 것을 목표로 한다.
- 기존 서비스와의 차이: 범용 메모앱과 달리 `기도제목`과 `묵상`이라는 두 기록
  형태를 구분하고, 묵상에는 성경 구절 참조를 구조화된 형태로 남긴다.

## 2. 서비스 구성

| 구성요소 | 사용하는 사람 | 역할 |
|---|---|---|
| iOS 앱 화면 | 사용자 | 기록 작성·조회·수정·삭제, 날짜별 탐색 |
| 기기 내 로컬 데이터 저장소 | 시스템 | 기록 데이터 저장 및 조회 |
| 기기 간 동기화(선택) | 시스템 | 기기 변경 시 데이터 이전. 도입 여부 미정([6. 미결정 사항](#6-미결정-사항) 참고) |

서버와 계정 시스템은 MVP 구성에 포함하지 않는다.

## 3. 핵심 기능 요구사항

### 3.1 기록 작성

#### 3.1.1 기도제목 등록

**목적**: 특정 날짜의 기도제목을 남겨 이후에 다시 찾아볼 수 있게 한다.

**기능 요구사항**:

- 사용자는 기록 날짜를 지정해 기도제목을 등록할 수 있어야 한다. 날짜의 기본값은
  오늘이며, 지난 날짜로도 변경할 수 있어야 한다.
- 사용자는 기도제목 내용을 여러 줄로 입력할 수 있어야 한다.
- 시스템은 하나의 날짜에 여러 건의 기도제목이 등록되는 것을 허용해야 한다.
- 시스템은 저장 시 기록 종류를 `기도제목`으로 구분해 보관해야 한다.

**예외 처리**:

- 내용이 비어 있는 경우: 저장을 진행하지 않고 입력이 필요하다는 안내를 표시한다.
- 저장에 실패한 경우: 작성 중인 내용을 화면에서 유지하고 실패 안내를 표시한다.

**완료 조건**:

- [ ] 오늘 날짜로 기도제목을 등록하면 목록에서 해당 날짜 아래에 보인다.
- [ ] 지난 날짜를 지정해 등록하면 그 날짜에 기록된다.
- [ ] 저장에 실패해도 입력한 내용이 사라지지 않고 안내가 표시된다.

#### 3.1.2 묵상 등록

**목적**: 묵상 내용을 성경 본문 위치와 함께 남겨 기록의 맥락을 보존한다.

**기능 요구사항**:

- 사용자는 기록 날짜를 지정해 묵상을 등록할 수 있어야 한다. 날짜의 기본값은
  오늘이며, 지난 날짜로도 변경할 수 있어야 한다.
- 사용자는 묵상 내용을 여러 줄로 입력할 수 있어야 한다.
- 사용자는 묵상에 성경 구절 참조를 기록할 수 있어야 한다. 참조는 다음 항목으로
  구성한다.
  - 성경 책 이름 (구약·신약 66권 중 선택)
  - 장
  - 절 또는 절 범위 (예: `16`, `16-17`)
  - 하나의 묵상에 여러 개의 구절 참조를 추가할 수 있어야 한다
    (예: `시편 23:1-6`과 `요한복음 10:11`을 함께 기록)
- 시스템은 입력된 참조를 `요한복음 3:16-17` 형식의 읽기 쉬운 문자열로 표시해야
  한다.
- 시스템은 저장 시 기록 종류를 `묵상`으로 구분해 보관해야 한다.

**예외 처리**:

- 내용이 비어 있는 경우: 저장을 진행하지 않고 입력이 필요하다는 안내를 표시한다.
- 절 범위가 뒤바뀐 경우(예: 시작 절 > 끝 절): 저장 전 안내를 표시하고 수정을
  요청한다.
- 성경 구절 참조를 입력하지 않은 경우: 참조 없이도 저장을 허용한다.
- 저장에 실패한 경우: 작성 중인 내용을 화면에서 유지하고 실패 안내를 표시한다.

**완료 조건**:

- [ ] 성경 책·장·절을 선택해 묵상을 저장하면 목록과 상세에서 `요한복음 3:16-17`
      형태로 참조가 보인다.
- [ ] 성경 구절 참조 없이도 묵상을 저장할 수 있다.
- [ ] 잘못된 절 범위를 입력하면 저장되지 않고 안내가 표시된다.

### 3.2 기록 조회 및 관리

#### 3.2.1 날짜별 기록 조회

**목적**: 어느 날짜에 어떤 기도제목과 묵상을 남겼는지 확인한다.

**기능 요구사항**:

- 시스템은 기록을 날짜 역순(최신 우선)으로 묶어 목록으로 보여야 한다.
- 목록의 각 항목은 기록 종류(기도제목·묵상), 내용 일부, 묵상인 경우 성경 구절
  참조를 함께 보여야 한다.
- 사용자는 기록 종류로 목록을 걸러 볼 수 있어야 한다(전체 / 기도제목 / 묵상).
- 사용자는 특정 기록을 선택해 전체 내용을 볼 수 있어야 한다.

**예외 처리**:

- 기록이 하나도 없는 경우: 첫 기록을 작성하도록 안내하는 빈 화면을 표시한다.

**완료 조건**:

- [ ] 여러 날짜에 걸친 기록이 날짜별로 묶여 최신순으로 표시된다.
- [ ] 종류 필터를 바꾸면 해당 종류의 기록만 표시된다.
- [ ] 기록이 없을 때 안내 화면이 표시된다.

#### 3.2.2 월간 캘린더 보기

**목적**: 어느 날에 기록을 남겼고 어느 날이 비어 있는지 한눈에 파악한다.

**기능 요구사항**:

- 기록 목록 화면에서 `목록` 보기와 `캘린더` 보기를 전환할 수 있어야 한다.
- 캘린더는 한 달을 격자로 표시하고, 기록이 있는 날짜에 표식을 붙여야 한다.
- 표식은 기도제목만 있는 날, 묵상만 있는 날, 둘 다 있는 날을 구별해야 한다.
- 종류 필터는 목록 보기와 캘린더 보기에 공통으로 적용되어야 한다.
- 이전 달·다음 달 이동과 오늘로 돌아오기를 제공해야 한다.
- 날짜를 선택하면 그 날짜의 기록 목록을 보여주어야 한다.

**예외 처리**:

- 기록이 없는 날짜를 선택한 경우: 빈 상태 안내를 표시한다.

**완료 조건**:

- [ ] 기록이 있는 날짜에만 표식이 표시된다.
- [ ] 종류에 따라 표식이 구별된다.
- [ ] 이전·다음 달 이동과 오늘로 돌아오기가 동작한다.
- [ ] 날짜 선택 시 해당 날짜 기록만 표시된다.

#### 3.2.3 기록 수정 및 삭제

**목적**: 잘못 적은 내용이나 날짜를 바로잡고, 필요 없는 기록을 정리한다.

**기능 요구사항**:

- 사용자는 기존 기록의 내용, 날짜, 성경 구절 참조를 수정할 수 있어야 한다.
- 사용자는 기록을 삭제할 수 있어야 한다.
- 시스템은 삭제 전 확인 절차를 제공해야 한다.

**예외 처리**:

- 저장·삭제에 실패한 경우: 기존 데이터를 변경하지 않고 실패 안내를 표시한다.

**완료 조건**:

- [ ] 기록을 수정하면 목록과 상세에 수정 결과가 반영된다.
- [ ] 삭제 시 확인 절차를 거치며, 확인 후 목록에서 사라진다.
- [ ] 실패 시 기존 기록이 손상되지 않는다.

#### 3.2.4 기록 내보내기 (소모임 나눔용)

**목적**: 소모임에서 나눌 때 기록을 그대로 꺼내어 카카오톡 등에 붙여 쓸 수 있게
한다.

**기능 요구사항**:

- 사용자는 기록 1건을 텍스트로 내보낼 수 있어야 한다. 날짜 묶음·기간 단위 공유는
  이번 범위에서 제외한다.
- 시스템은 iOS 기본 공유 기능을 통해 다른 앱으로 텍스트를 전달해야 한다.
- 내보내는 텍스트에는 날짜, 기록 종류, 성경 구절 참조, 내용이 포함되어야 한다.

**예외 처리**:

- 공유가 취소된 경우: 아무 변경 없이 원래 화면으로 돌아간다.

**완료 조건**:

- [ ] 기록을 공유하면 카카오톡·메모 등 다른 앱에 날짜와 내용이 포함된 텍스트가
      전달된다.

## 4. MVP 개발 범위

### 4.1 MVP 목표

계정 없이 기기 안에서, 날짜와 성경 구절이 함께 남는 기록 작성·조회 흐름이 실제로
매일 쓸 만한지 검증한다.

### 4.2 반드시 구현할 기능

**소모임 참여 크리스천 (단일 사용자)**:

- 날짜를 지정한 기도제목 등록
- 날짜를 지정한 묵상 등록 (성경 책·장·절 참조 포함)
- 날짜별 기록 목록 조회 및 종류 필터
- 월간 캘린더 보기 (기록이 있는 날짜 표시)
- 기록 상세 보기, 수정, 삭제
- 기록 1건 텍스트 내보내기(공유)
- 전체 기록 JSON 백업 내보내기·가져오기

### 4.3 나중에 구현할 기능

- 기록 검색 (내용·성경 구절 기준)
- 기도제목 응답 표시 및 응답 내용 기록
- iCloud 기기 간 동기화
- 소모임 단위 공동 나눔 공간
- 기록 작성 리마인더 알림
- 앱 잠금(Face ID/암호)
- 안드로이드 지원
- 태그·주제 분류

명확히 제외하는 기능은 [`constraints.md`](constraints.md)의 `제외 기능`에 정리한다.

## 5. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 성능 | 앱 실행부터 기록 목록 표시까지 일반적인 기기에서 2초 이내. 기록 저장은 즉시 반영 |
| 오프라인 | 네트워크 연결 없이 모든 기능이 동작해야 한다 |
| 보안 | 기록은 기기 내부에 저장하고 외부 서버로 전송하지 않는다. 계정·인증은 두지 않는다 |
| 가용성/복구 | 앱이 강제 종료되거나 저장에 실패해도 작성 중이던 내용이 유지되어야 한다 |
| 지원 환경 | iOS 17 이상(iPhone). iPad·안드로이드·웹은 대상 아님 |
| 접근성 | 시스템 글자 크기(Dynamic Type) 반영, VoiceOver로 기록 읽기 가능, 텍스트 대비 확보. 캘린더 표식을 색상만으로 구분하지 않음 |
| 데이터 이전 | JSON 백업 파일 내보내기·가져오기로 기기 변경에 대응한다 |

## 7. 부록

### 7.1 용어 정의

| 용어 | 의미 |
|---|---|
| 기록 | 이 앱에 저장되는 한 건의 항목. 기도제목 또는 묵상 |
| 기도제목 | 특정 날짜에 기도하려는 내용을 적은 기록 |
| 묵상 | 특정 성경 본문을 읽고 느낀 바를 적은 기록 |
| 성경 구절 참조 | 묵상의 근거가 되는 본문 위치. 책 이름, 장, 절(범위)로 구성 |
| 소모임 | 사용자가 기도제목과 묵상을 함께 나누는 오프라인 모임 |
| MVP | 최소 기능 제품. 첫 출시에 반드시 포함되는 범위 |
