## Question 1: 단위 분할 기준

가장 중요한 결정입니다. 같은 13개 기능을 어떤 축으로 자를지에 따라 진행 체감이
달라집니다.

A) **계층 우선 (3단위)** — 실행 계획의 초안 방식
   - Unit 1: 데이터·도메인 기반 (모델, 저장소, 검증, 참조 문자열화, 66권 데이터)
   - Unit 2: 기록 작성·조회 화면 (2탭, 작성, 목록, 상세, 수정, 삭제, 공유)
   - Unit 3: 캘린더·백업
   - 특징: 기반이 먼저 완성되어 화면 구현 중 모델을 되돌릴 일이 없다. Unit 1 완료
     시점에는 화면이 없어 단위 테스트로만 검증한다.

B) **기능 수직 분할 (3단위)** — 각 단위가 화면까지 포함
   - Unit 1: 기도제목 기록 흐름 전체 (모델·저장소·검증 최소 + 오늘 탭 + 작성 + 목록)
   - Unit 2: 묵상과 성경 구절 (참조 모델·검증·66권 선택 + 묵상 작성 + 상세·수정·삭제·공유)
   - Unit 3: 캘린더·백업
   - 특징: Unit 1 완료 시점에 실행되는 앱을 볼 수 있다. 대신 Unit 2에서 모델과
     저장소, 이미 만든 화면을 다시 손댄다.

C) **2단위로 축소**
   - Unit 1: 기반 + 핵심 화면 (FR-01 ~ FR-10)
   - Unit 2: 캘린더 + 백업 (FR-11 ~ FR-13)
   - 특징: 승인 지점이 줄어 빠르다. 대신 Unit 1이 커서 한 번에 검토할 코드량이 많다.
