### 2.3 답변 해석 메모

- **D-15 + D-17 조합**: 입력은 내장 66권 목록 선택 방식이며, 목록 화면에 검색
  입력이 있어 약칭(`요`, `창`)으로도 찾을 수 있다. 저장과 표시는 정식 명칭
  기준으로 통일한다. 자유 텍스트 입력은 허용하지 않는다.
- **D-14 vs D-18 구분**: `공유`와 `백업`은 서로 다른 기능이다.
  - 공유: 기록 1건을 사람이 읽는 텍스트로 iOS 공유 시트에 전달 (카톡 붙여넣기 용도)
  - 백업: 전체 기록을 JSON 파일로 내보내고 다시 가져오기 (기기 변경 용도)
- **D-10 + D-27 조합**: 첫 화면은 오늘 중심 화면(Q2=B)을 유지하고, 월간
  캘린더(Q2=C)는 `기록` 탭의 두 번째 보기 방식으로 추가한다. 탭은 `오늘`과 `기록`
  두 개를 유지한다. 캘린더를 별도 탭으로 분리하지 않은 이유는 목록 보기와 동일한
  데이터를 다른 형태로 보여주는 기능이며, 종류 필터를 두 보기에 공통 적용하기 위해서다.

## 3. 기능 요구사항

### FR-01 기록 작성 진입 (D-09, D-10)

- 앱 첫 화면(`오늘` 탭)에 `기도제목 작성`과 `묵상 작성` 버튼을 각각 제공한다.
- 각 버튼은 해당 종류로 고정된 작성 화면을 연다. 작성 화면에서 종류를 바꾸는
  수단은 제공하지 않는다.

**완료 조건**
- [ ] 오늘 탭에 두 개의 작성 버튼이 보인다.
- [ ] `기도제목 작성`으로 진입하면 성경 구절 입력 영역이 없다.
- [ ] `묵상 작성`으로 진입하면 성경 구절 입력 영역이 있다.

### FR-02 기도제목 등록 (D-11, D-12)

- 기록 날짜를 지정할 수 있다. 기본값은 오늘이며 과거·미래 날짜로 변경 가능하다.
- 제목은 선택 입력이다. 비워두면 목록에서 내용 앞부분을 제목 위치에 표시한다.
- 내용은 여러 줄 입력이며 필수다.
- 같은 날짜에 여러 건 등록할 수 있다.
- 저장 시 종류는 `기도제목`으로 고정된다.

**예외**
- 내용이 공백만으로 이루어진 경우 저장하지 않고 안내를 표시한다.
- 저장 실패 시 작성 중 내용을 화면에 유지하고 안내를 표시한다.

**완료 조건**
- [ ] 제목 없이 저장하면 목록에 내용 앞부분이 제목 위치에 표시된다.
- [ ] 같은 날짜에 2건 이상 저장되고 목록에서 모두 보인다.
- [ ] 공백만 입력하면 저장되지 않는다.

### FR-03 묵상 등록 (D-06, D-11, D-12, D-16)

- FR-02의 날짜·제목·내용 규칙을 동일하게 적용한다.
- 성경 구절 참조를 0개 이상 추가할 수 있다. 참조 없이도 저장 가능하다.
- 각 참조는 성경 책, 장, 시작 절(선택), 끝 절(선택)로 구성한다.
- 참조 추가·삭제·순서 확인이 작성 화면에서 가능해야 한다.
- 저장 시 종류는 `묵상`으로 고정된다.

**예외**
- 시작 절 없이 끝 절만 입력한 경우 저장하지 않고 안내를 표시한다.
- 끝 절이 시작 절보다 작은 경우 저장하지 않고 안내를 표시한다.
- 장이 1 미만이거나 정수가 아닌 경우 저장하지 않고 안내를 표시한다.

**완료 조건**
- [ ] 참조를 2개 이상 추가한 묵상이 저장되고 상세에서 모두 보인다.
- [ ] 참조 없는 묵상이 저장된다.
- [ ] `시편 23장`처럼 절 없이 저장된다.
- [ ] 끝 절 < 시작 절이면 저장되지 않는다.

### FR-04 성경 책 선택 (D-05, D-15, D-17)

- 앱에 구약·신약 66권 목록을 내장한다. 각 항목은 정식 명칭, 약칭 목록, 정경 순서,
  구약/신약 구분을 갖는다.
- 선택 화면에서 검색 입력을 제공하고, 정식 명칭과 약칭 모두로 검색된다.
- 목록은 정경 순서로 정렬한다.
- 성경 번역 본문은 어떤 형태로도 포함하지 않는다.

**완료 조건**
- [ ] `요`로 검색하면 요한복음, 요한일서, 요엘 등 약칭·명칭이 일치하는 책이 나온다.
- [ ] 66권 전체가 정경 순서로 표시된다.
- [ ] 앱 어디에도 성경 본문 텍스트가 포함되지 않는다.

### FR-05 성경 구절 참조 표시 (D-16)

- 참조는 다음 규칙으로 문자열화한다.
  - 절 없음: `요한복음 3장`
  - 단일 절: `요한복음 3:16`
  - 절 범위: `요한복음 3:16-17`
- 참조가 여러 개면 입력 순서대로 `, `로 이어 표시한다.

**완료 조건**
- [ ] 세 가지 형태가 규칙대로 표시된다.
- [ ] 참조 2개가 입력 순서대로 이어져 표시된다.

### FR-06 오늘 화면 (D-10)

- `오늘` 탭은 오늘 날짜의 기록 목록과 두 개의 작성 버튼을 표시한다.
- 오늘 기록이 없으면 작성을 유도하는 빈 상태를 표시한다.
- 목록 항목을 선택하면 상세 화면으로 이동한다.

**완료 조건**
- [ ] 오늘 저장한 기록이 즉시 오늘 탭에 나타난다.
- [ ] 과거 날짜로 저장한 기록은 오늘 탭에 나타나지 않는다.
- [ ] 오늘 기록이 없으면 빈 상태 안내가 보인다.

### FR-07 전체 기록 목록 (D-08, D-27)

- `기록` 탭은 `목록`과 `캘린더` 두 가지 보기 방식을 제공하고, 사용자가 전환할 수
  있다. 기본 보기는 `목록`이다.
- 목록 보기는 전체 기록을 날짜 역순으로 표시하고, 같은 날짜 기록을 하나의 그룹으로
  묶는다.
- 종류 필터를 제공한다: 전체 / 기도제목 / 묵상. 필터는 목록 보기와 캘린더 보기에
  공통으로 적용된다.
- 각 항목은 종류, 제목(또는 내용 앞부분), 내용 미리보기, 묵상인 경우 참조 문자열을
  표시한다.
- 기록이 하나도 없으면 빈 상태를 표시한다.

**완료 조건**
- [ ] 여러 날짜 기록이 날짜별로 묶여 최신순으로 표시된다.
- [ ] 필터를 `묵상`으로 바꾸면 기도제목이 표시되지 않는다.
- [ ] 필터 상태와 보기 방식은 화면을 벗어났다 돌아와도 유지된다.
- [ ] 보기 전환 컨트롤로 목록과 캘린더를 왕복할 수 있다.

### FR-08 기록 상세 및 수정 (D-11, D-12, D-16)

- 상세 화면은 날짜, 종류, 제목, 내용 전문, 참조 전체를 표시한다.
- 수정 화면에서 날짜, 제목, 내용, 참조를 변경할 수 있다. 종류는 변경할 수 없다.
- 수정 시 FR-02·FR-03의 검증 규칙을 동일하게 적용한다.

**완료 조건**
- [ ] 수정 결과가 목록과 상세에 즉시 반영된다.
- [ ] 잘못된 참조로 수정하면 저장되지 않고 기존 데이터가 유지된다.

### FR-09 기록 삭제 (D-13)

- 상세 화면에서 기록을 삭제할 수 있다.
- 삭제 전 확인 다이얼로그를 표시하고, 확인 시 즉시 완전 삭제한다.
- 복구 수단은 제공하지 않으며, 확인 다이얼로그에 복구 불가임을 명시한다.

**완료 조건**
- [ ] 확인 다이얼로그에서 취소하면 기록이 유지된다.
- [ ] 확인하면 목록과 저장소에서 제거된다.
- [ ] 다이얼로그에 복구 불가 안내가 포함된다.

### FR-10 기록 1건 공유 (D-07, D-14)

- 상세 화면에서 기록 1건을 텍스트로 공유할 수 있다.
- iOS 공유 시트를 사용해 다른 앱에 텍스트를 전달한다.
- 공유 텍스트 구성: 날짜, 종류, 제목(있는 경우), 참조 문자열(묵상), 내용 전문.

**예외**
- 공유가 취소되면 아무 변경 없이 원래 화면으로 돌아간다.

**완료 조건**
- [ ] 공유 시트에서 메모 앱 등에 붙여넣으면 날짜·종류·내용이 포함된 텍스트가 들어간다.
- [ ] 묵상 공유 텍스트에 참조 문자열이 포함된다.

### FR-11 백업 내보내기 (D-18, D-19)

- 전체 기록을 단일 JSON 파일로 내보낼 수 있다.
- 파일에는 스키마 버전, 내보낸 시각, 기록 배열이 포함된다.
- 파일 저장 위치는 사용자가 선택한다(파일 앱, iCloud Drive 등).
- 내보내기 화면에 이 파일이 암호화되지 않은 평문이며 기록 내용이 그대로 담긴다는
  안내를 표시한다.

**완료 조건**
- [ ] 기록이 있는 상태에서 JSON 파일이 생성되고 저장된다.
- [ ] 파일에 스키마 버전 필드가 있다.
- [ ] 평문 안내 문구가 표시된다.

### FR-12 백업 가져오기 (D-18, D-19)

- 내보낸 JSON 파일을 선택해 기록을 복원할 수 있다.
- 가져오기 전 병합 방식을 사용자에게 확인한다: 기존 기록 유지하며 추가 / 전체 교체.
- 동일 식별자의 기록이 이미 있으면 중복 생성하지 않는다.
- 스키마 버전이 지원 범위를 벗어나면 가져오기를 중단하고 안내한다.
- 파일 구조나 필드가 유효하지 않으면 어떤 기록도 저장하지 않고 중단한다(전부 성공
  또는 전부 실패).

**예외**
- JSON 파싱 실패, 필수 필드 누락, 타입 불일치, 허용 범위 초과 값이 있으면 중단하고
  사용자에게 실패 이유를 일반적인 문구로 안내한다.

**완료 조건**
- [ ] 내보낸 파일을 가져오면 기록 건수와 내용이 원본과 일치한다.
- [ ] 같은 파일을 두 번 가져와도 기록이 중복되지 않는다.
- [ ] 손상된 JSON을 가져오면 기존 데이터가 변경되지 않는다.
- [ ] 지원하지 않는 스키마 버전이면 중단되고 안내가 표시된다.

### FR-13 월간 캘린더 보기 (D-27)

- `기록` 탭의 `캘린더` 보기는 한 달을 격자로 표시하고, 기록이 있는 날짜에 표식을
  붙인다.
- 표식은 기록 종류를 구분한다. 기도제목만 있는 날, 묵상만 있는 날, 둘 다 있는 날을
  시각적으로 구별할 수 있어야 한다.
- 종류 필터가 적용된 상태에서는 해당 종류의 기록이 있는 날짜만 표식을 표시한다.
- 이전 달·다음 달로 이동할 수 있고, 오늘이 포함된 달로 즉시 돌아오는 수단을 제공한다.
- 오늘 날짜는 기록 유무와 무관하게 항상 구별되게 표시한다.
- 날짜를 선택하면 그 날짜의 기록 목록을 같은 화면에서 보여주고, 항목을 선택하면
  상세 화면으로 이동한다.
- 기록이 없는 날짜를 선택하면 빈 상태를 표시한다.
- 캘린더 조회는 표시 중인 달의 범위로 한정한다. 전체 기록을 메모리에 적재하지 않는다.

**접근성**
- VoiceOver로 날짜를 읽을 때 기록 유무와 종류를 함께 전달해야 한다. 표식을 색상만으로
  구분하지 않는다.

**완료 조건**
- [ ] 기록이 있는 날짜에 표식이 보이고, 없는 날짜에는 보이지 않는다.
- [ ] 기도제목만 있는 날과 묵상만 있는 날의 표식이 구별된다.
- [ ] 필터를 `묵상`으로 두면 기도제목만 있는 날짜의 표식이 사라진다.
- [ ] 이전·다음 달로 이동하고 오늘로 돌아올 수 있다.
- [ ] 날짜를 선택하면 그 날짜의 기록만 표시되고, 선택 시 상세로 이동한다.
- [ ] VoiceOver로 날짜를 읽을 때 기록 유무가 음성으로 전달된다.

### 4.2 설계 제약

- **CloudKit 전방 호환** (D-18): iCloud 동기화를 다음 버전에 추가하기로 했으므로,
  MVP 모델부터 SwiftData + CloudKit 제약을 지킨다.
  - 모든 저장 속성은 옵셔널이거나 기본값을 가진다.
  - 유니크 제약(`@Attribute(.unique)`)을 사용하지 않는다.
  - 관계는 옵셔널로 선언하고 역참조를 정의한다.
  - 이 제약을 지키지 않으면 다음 버전에서 마이그레이션 비용이 발생한다.
- **장·절 상한 검증 없음**: 책별 실제 장 수와 절 수 검증은 하지 않는다. 정확한
  데이터를 내장해야 하고 번역본에 따라 차이가 있어 오탐 위험이 크다. `1 이상 정수`
  범위 검증까지만 수행한다.
- **날짜 저장**: 기기 로컬 시간대 기준 일 단위로 정규화해 저장한다. 시간대 변경 시
  기록 날짜가 바뀌지 않아야 한다.
